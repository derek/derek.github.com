The blogs and the feed reader: an industry run by correspondence

For about nine years the working knowledge of front-end development lived on a few dozen personal websites, and one tag in the <head> was how it reached you.

<link rel="alternate"
  type="application/rss+xml"
  href="rss-feed">

That is the example from the RSS Advisory Board's autodiscovery specification, wrapped onto three lines. It tells a browser or a feed reader that this page has a machine-readable twin. You never typed it. Your publishing software wrote it, and you saw only its effect: a small orange square that lit up in the address bar.

The tag did a job that sounds minor. It let developers subscribe to each other. Between roughly 2004 and 2013, that turned out to be how the field decided what good JavaScript looked like. In 2004 there was no Stack Overflow and no GitHub, and nobody had written down in one place what each browser actually did. There were people with a domain, a comment form and a feed, and there was the program you read them in.

Before: bookmarks and reload

Following a website in 2001 meant visiting it. You kept a folder of bookmarks, opened each one and looked for anything new. A site that updated twice a year cost you the same daily visit as one that updated twice a day, so in practice you stopped visiting the slow ones, and the slow ones were often the best.

The fix had existed since the 1990s. Netscape shipped the first version of RSS in March 1999 for its My Netscape portal, according to Wikipedia's history of the format. Netscape then dropped out, and two camps carried the format forward without it. One produced RSS 1.0. The other was Dave Winer, whose RSS 2.0 arrived in 2002 and is the version still published as the specification. A third group, tired of both, started over in 2003 with a format called Atom, which became an IETF standard in 2005.

So by the middle of the decade there were at least three incompatible ways to say "here are my ten newest entries." When David Pierce of The Verge asked Chris Wetherell how Google Reader began, Wetherell's answer was: "a raging battle between feed formats." The formats never merged. The readers simply learned to parse all of them, which is the web's usual way of settling a standards war.

The readers came in two kinds: programs you installed, like NetNewsWire, and websites you logged in to. The best known of the early websites was Bloglines, which launched in 2003 and was sold to Ask Jeeves in February 2005. The browsers followed. In December 2005 the Internet Explorer and Outlook teams announced they would use the orange icon that a Mozilla designer, Stephen Horlander, had drawn for Firefox, a rare case of Microsoft adopting a competitor's picture on purpose. That detail is in Wikipedia's article on web feeds. By the time the autodiscovery spec was written down in November 2006, it could say that Firefox 2.0 and Internet Explorer 7.0 both lit the icon when they found the tag.

QuirksMode: a one-person lab

The feed was only plumbing. What flowed through it was mostly written by people nobody had hired to write it.

Take Peter-Paul Koch, a freelancer in Amsterdam who signed as ppk. Koch tested what every browser actually did with every DOM method and CSS property, and published the results as tables. Koch's own About page describes the site this way: "This site QuirksMode.org used to be MDN and caniuse rolled into one, and I maintained it by myself, mostly unpaid, from 1999 to around 2014." The same page says that from Safari's release in 2003 until the iPhone in 2007, Apple pointed to QuirksMode for the documentation of JavaScript in "Safari and other browsers." A browser vendor's JavaScript documentation was, by this account, a link to one person's website.

The tables were the reference. The argument happened next door, on QuirksBlog, whose monthly archives begin in 2004. In July of that year Koch opened an entry with the sentence "The new buzz word is definitely 'Web Applications'" and complained that nobody had bothered to define the term. Seven months later Jesse James Garrett's essay of February 18, 2005 gave the thing a four-letter name. I mention the dates because they show the order of events in this period: the people with blogs were arguing about a technique before it had a name, a book or a conference.

A conversation in function form

Here is what that argument looked like when it worked. In the spring of 2004 Koch argued that inline event handlers such as onclick="" did not belong in HTML files. On May 26, Simon Willison answered on a different site, in an entry called "Executing JavaScript on page load". It quotes Koch, links to QuirksMode, credits a function by a third blogger, Scott Andrew, points out that the function "fails silently in IE5/Mac," and then says: "Anyway, I believe I've found a solution. Check this out:"

function addLoadEvent(func) {
  var oldonload = window.onload;
  if (typeof window.onload != 'function') {
    window.onload = func;
  } else {
    window.onload = function() {
      if (oldonload) {
        oldonload();
      }
      func();
    }
  }
}

You probably pasted this. It solves a problem that sounds too small to need solving: two scripts on one page both want to run at load, and window.onload holds only one function, so the second script silently evicts the first. The closure keeps the old handler alive and calls it before the new one.

Now look at the listing as a piece of publishing. It names its browser test matrix in prose. It asks for bug reports. And at the bottom of the page is a note dated May 28, 2006: a reader named Billy Pan had found that the code threw a runtime error in IE 7, his fix was the if (oldonload) line, and it had been "rolled in to the code shown above." A bug report came in, a patch was accepted and the release was updated, two years after publication, on a personal weblog. This is a pull request, carried out with the tools available.

The next year the same circle made the process explicit. In August 2005 Koch published an entry titled "addEvent() considered harmful," and on September 8 he opened a contest to rewrite the function. Entries were submitted as comments. The judges were Koch, Scott Andrew LePera and Dean Edwards. The prize, in the entry's words, "will consist of eternal and undying fame." On October 18 they named the winner, a 15-line entry from John Resig, and then listed three bugs in it, because that was the house style. What Resig did with the fame is the subject of the jQuery essay.

Ajaxian: the front page

A few dozen blogs is too many to keep in your head, which created a second job: someone to read all of them and tell you which entries mattered.

On March 14, 2005, less than a month after Garrett's essay, Dion Almaer announced a new site on a personal blog: "Ben and I have had great feedback from the presentations that we have given on Ajax, so we created Ajaxian.com, as a place to talk about all things Ajax." Ben was Ben Galbraith. The first topic Almaer mentions is the back button, which tells you how early this was.

Ajaxian became the place where a library release or a clever hack went to be noticed. It wrote up other people's work and ran monthly roundups; Frontend Dogma's archive still indexes them, with titles like "Ajaxian Roundup for April 2008: CSS Goodness, Ext Licenses, and the Cloud." By May 2006 Almaer was on the bill of a three-day conference called The Ajax Experience. The same archive lists an October 2008 entry, "Ajaxians Join Mozilla, Creating a Developer Tools Group." A link roundup had turned into a conference circuit and then into jobs at a browser maker.

You can see what a mention was worth in the way authors counted. When Resig reviewed the jQuery 1.3 launch in February 2009, the traffic sources were listed in this order: "we hit Ajaxian, Reddit, Hacker News, and a number of blogs." A few months earlier, offering a site called MiniAjax.com for sale, Resig described its value in the units of the day: "20,900 adds on Delicious," "4,500 – 5,000 Daily Feed Subscribers," "Technorati Authority of 93." Feed subscribers were a line on the asking price.

The front page did not get the last word, either. After Almaer and Galbraith opened the @media Ajax conference in London in November 2007, Jeremy Keith wrote that evening that "the Ajaxians are missing the core attributes that make the Web so appealing—things like hypertext and markup, to which technologies like JavaScript and Ajax should be subservient." It is the argument about how much of a page should be JavaScript, and the industry is still having it. In 2007 it was being had between two blogs, in public, with permalinks.

Google Reader: the inbox

All of this needed somewhere to land. For most developers, from late 2006 on, that was one browser tab.

The Verge's history has the origin. In late 2004 Jason Shellen, a product manager at Google, asked Wetherell for "just a little thing that would parse Atom" as a demo. Wetherell built a JavaScript app in a night, called it Fusion, and then caught himself using it to read. It grew in 20 percent time. The name was taken away at the last minute, and the replacement was one Wetherell says "none of us liked."

Google Reader launched on October 7, 2005. Wetherell's announcement said the team often got asked "how anyone's supposed to keep up with the firehose of stuff launched from the web's spigot." Then, in Wetherell's words to The Verge: "it bombed. It was terrible." The site fell over on the first day and the interface confused people.

The version you used was the second one. On September 28, 2006, Ben Darnell announced a rebuild with "a clean interface and some JavaScript wizardry," and the two features that still define a feed reader: "unread counts and 'mark all as read.'" The same release added a "shared" icon that put an item on a public page "for your friends to see." Mihai Parparita, one of the engineers, told The Verge that people spent "like an hour a day in Reader." At its peak, the article says, Reader had "just north of 30 million users."

For a working developer the effect was a newspaper that assembled itself. QuirksBlog, Ajaxian, Resig, Willison, Keith and a hundred others arrived in one list, newest first, with a number beside each. The number was the catch. An inbox you did not ask for is still an inbox, and "mark all as read" got used a great deal.

Why a few blogs could run a field

The documentation was missing. Browser makers documented their own browser, when they documented anything, and nobody documented the differences. The differences were the job. Whoever tested them and published the table became the reference by default, and Koch's About page is right to call the result MDN and caniuse in one.

Publishing got cheap and addressable at the same moment. Blog software gave every entry a permanent URL, a comment form and a feed for free. A permanent URL can be cited, and a comment form on it is where the corrections arrive. Add the feed and each correction reaches every subscriber by morning. I'd argue that is most of what peer review is, and it came bundled with the software.

Fame was a real currency. Koch's prize of "eternal and undying fame" was a joke with a business model inside it. Nobody was paid per entry. What a good entry bought was a book contract, a conference invitation or a job. Koch's first book came out in 2007, and the Ajaxian founders went to Mozilla. This is my reading of the incentives, but the careers are on the record.

Why it stopped

Google wanted a social network, and Reader was in the way. The Verge's account is that Reader was put into "maintenance mode" by early 2011 while its engineers were pulled into Google Plus. On October 20, 2011, the Reader team announced that "we'll be retiring things like friending, following and shared link blogs inside of Reader," since those would "soon be available via Google+." On March 13, 2013, the end came as one paragraph in a list of housekeeping items signed by Urs Hölzle: "While the product has a loyal following, over the years usage has declined. So, on July 1, 2013, we will retire Google Reader." Parparita told The Verge that the announcement was timed for the day a new pope was elected, on the theory that the pope would be the story. The theory was wrong. The Next Web reported that Feedly, a rival reader, picked up 500,000 new users in 48 hours.

The blog's jobs were split up among better tools. A 2005 blog entry was a question-and-answer thread, a code host and a link feed all at once. In April 2008 Jeff Atwood announced Stack Overflow, on a blog, with this reasoning: "Blogs are fantastic resources, but as much as I might encourage my fellow programmers to blog, not everyone has the time or inclination to start a blog." GitHub launched the same month, and code that would once have been pasted into an entry went into a repository with an issue tracker. The links, by my reading, went to Twitter, Reddit and Hacker News. Resig's 2009 traffic list already has two of those three sitting beside Ajaxian.

The work was unpaid, and people got tired. Koch's About page is blunt about it: "I ceased working on this site because it was mostly unpaid and I was getting burned out after 15 years." That sentence covers more of the era than one site. A reference library maintained by one freelancer for fifteen years is impressive, and it is also a staffing plan nobody would have signed off on.

It is fair to say Google's stated reason was not false. Feed reading had always been a habit of the people who read a lot, and The Verge notes that the Reader team "struggled to find ways to bring in more casual users." Everyone else was getting their links from a timeline by 2013. Firefox finished the retreat on December 11, 2018, when version 64 noted that "RSS feed preview and live bookmarks are available only via add-ons." The orange square left the address bar.

What the feed era left behind

RSS won a different market. The RSS 2.0 specification has an element called <enclosure> that attaches a media file to an item. Its example is an MP3:

<enclosure url="http://www.scripting.com/mp3s/weatherReportSuite.mp3" length="12216320" type="audio/mpeg" />

That one element is the podcast industry. Apple's current requirements for podcasters say feed URLs "must adhere to RSS 2.0 specifications." The format that supposedly died in 2013 is the distribution layer for a whole medium. It just stopped being called a feed.

The newsletter is a feed reader with an editor in it. JavaScript Weekly launched in November 2010, a few months before Reader went into maintenance mode, and its site now counts more than 800 issues. It does Ajaxian's old job, reading everything and passing on what matters, and delivers the result to the one inbox nobody has managed to shut down. It also solves the unread count: one message a week, and no number in the sidebar accusing you of anything.

Reader was the social network Google was looking for. This is the connection I think gets missed. Follow a person, see what they share, comment on it: Reader had sharing in 2006, grew the rest in the years after, and Google retired it all in 2011 to promote a product that did the same thing with less to read. Shellen told The Verge, "I think we built a social product." The article also notes that Kevin Systrom, who had been a product marketing manager on Reader, went on to found Instagram. The feed of things from people you chose to follow did become the dominant interface of the next decade. It was just built elsewhere, and without the open format underneath.

The personal sites outlasted the front page. Every source in this essay had to be opened, and what loaded is its own finding. Willison's 2004 entry is still up, carrying a note that it was "previously hosted at" an older address, and a weblog that has run since 2002 is still running. Koch's 2005 contest is still at its original URL. Ajaxian.com did not answer at all when I tried it, and Dean Edwards's site returned a note that the server "is having a nice rest." The aggregator with the audience turned out to be the fragile part. The primary sources were on domains that individuals kept paying for.

The takeaway

From about 2004 to 2013, front-end development was run by correspondence. People published what they had found on their own sites, other people answered on theirs, a couple of aggregators picked the winners, and a feed reader delivered the whole exchange to your desk each morning. Functions like addLoadEvent were specified, reviewed, patched and distributed that way, years before the standards bodies or the code hosts caught up. It worked because publishing was cheap, the browser makers had left the documentation to volunteers, and reputation paid well enough to keep the volunteers writing.

It ended when each job found a better home and the main reading room was closed by a company that wanted its readers elsewhere. The lesson I'd take from it is about what lasts. The platform with thirty million users was gone in eight years. The open format is still carrying every podcast, and the entries written on personal domains are still there to be read. If you want something you write to be findable in twenty years, the evidence favors a plain page at an address you control, with a feed.
